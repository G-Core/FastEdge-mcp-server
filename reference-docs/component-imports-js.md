# Component Imports — JavaScript/TypeScript Reference

## When to Use a Component

Use a Wasm component when:

- A library or existing code you need is written in another language (Rust, Go, TinyGo, C/C++, Python, etc.).
- A hot path needs native speed.

For anything JavaScript already does well, plain JS is simpler.

Component imports require `@gcoredev/fastedge-sdk-js` 2.7.0 or later.

A Wasm component is a compiled module with a typed interface described in WIT (WebAssembly Interface Types). `fastedge-build` composes the component into the application's Wasm output, producing a single binary.

---

## Build Configuration

Map each WIT interface to its component file using the `components` field in `.fastedge/build-config.js` or the repeatable `--component` CLI flag.

### `components` field (build config)

| Field        | Type                     | Required | Description                                                                                    |
| ------------ | ------------------------ | -------- | ---------------------------------------------------------------------------------------------- |
| `components` | `Record<string, string>` | No       | Map of WIT interface name to component file path, relative to the working directory.           |

Key format: `"namespace:package/interface"` (optionally followed by `@version`).  
Value: relative path to the `.wasm` component file.

**Example — build config:**

```js
export const config = {
  type: 'http',
  tsConfigPath: './tsconfig.json',
  entryPoint: './src/index.ts',
  wasmOutput: './dist/component-imports.wasm',
  components: {
    'example:image/thumbnail': './thumbnail.wasm',
  },
};
```

### `--component` flag (CLI)

| Flag          | Form                            | Repeatable | Description                                                                      |
| ------------- | ------------------------------- | ---------- | -------------------------------------------------------------------------------- |
| `--component` | `<interface>=<path>`            | Yes        | Same mapping as the config field. The first `=` separates interface name from path. |

**Example — CLI:**

```sh
fastedge-build -i src/index.ts -o dist/component-imports.wasm -t tsconfig.json \
  --component example:image/thumbnail=./thumbnail.wasm
```

### Several Components

One build may import interfaces from several component files, and several interfaces from one file. List each interface separately:

```js
components: {
  'acme:calc/arith': './calculator.wasm',
  'acme:calc/format': './calculator.wasm',
  'example:image/thumbnail': './thumbnail.wasm',
},
```

CLI equivalent — repeat `--component`:

```sh
fastedge-build -i src/index.ts -o dist/app.wasm -t tsconfig.json \
  --component acme:calc/arith=./calculator.wasm \
  --component acme:calc/format=./calculator.wasm \
  --component example:image/thumbnail=./thumbnail.wasm
```

Two component files that export the same interface cannot be used in one build; see Known Limitations.

For other build options, see the BUILD_CLI reference.

## Generated Type Declarations

On every build that includes components, `fastedge-build` reads each interface from its component and writes TypeScript declarations to `fastedge-components.d.ts` next to the entry file before type-checking.

- The application is type-checked against this file; a call with wrong types fails the build.
- `fastedge-components.d.ts` is the authoritative description of a component's types.
- Do not edit it manually; it is regenerated on every build.

**Example header and module block:**

```ts
// Generated by fastedge-build from the configured components. Do not edit.

declare module 'example:image/thumbnail' {
  // …types and functions for the interface
}
```

## WIT to JS Types

| WIT                                  | JS / TypeScript                                                                  |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| `bool`                               | `boolean`                                                                        |
| integers up to 32 bits, `f32`, `f64` | `number`                                                                         |
| `u64` `s64`                          | `bigint`                                                                         |
| `char`, `string`                     | `string`                                                                         |
| `list<u8>`                           | `Uint8Array`                                                                     |
| `list<f64>`                          | `Float64Array` (other number lists use the matching typed array)                 |
| `list<string>`                       | `string[]`                                                                       |
| `record`                             | object; kebab-case field names become camelCase (`max-width` → `maxWidth`)       |
| `enum`                               | string union (`'jpeg' \| 'png'`)                                                 |
| `option<T>`                          | `T \| undefined`                                                                 |
| `result<T, E>`                       | returns `T`; an error is thrown with the `E` value in `error.payload`            |
| `resource`                           | class                                                                            |

The generated `fastedge-components.d.ts` is the authoritative description of a given component's types.

## Calling and Errors

- Import functions by interface name, like a JS module: `import { resize } from 'example:image/thumbnail'`.
- Calls are **synchronous** and return the result directly. There is no `await`.
- Arguments and results are **copied** between the application and the component on every call. A large `Uint8Array` passed to a component is held in both memories while the call runs.

### WIT `result` errors

A WIT `result<T, E>` returns `T` on success. On error it throws an `Error` whose `payload` property holds the `E` value.

**Example — try/catch for `result<size, string>`:**

```ts
import { dimensions } from 'example:image/thumbnail';

function handle(bytes: Uint8Array): Response {
  try {
    const { width, height } = dimensions(bytes);
    return new Response(`${width}x${height}`);
  } catch (error) {
    // A WIT `result` error is thrown, with the component's message in `payload`
    return new Response(`Cannot read image: ${(error as { payload: string }).payload}`, {
      status: 415,
    });
  }
}

async function respond(request: Request): Promise<Response> {
  return handle(new Uint8Array(await request.arrayBuffer()));
}

addEventListener('fetch', (event: FetchEvent) => event.respondWith(respond(event.request)));
```

## Resources

A WIT `resource` becomes a JS class: its `constructor` becomes the class constructor, its methods become instance methods, and `static` functions become static methods. The generated class implements `Disposable`.

**WIT definition:**

```wit
package acme:calc;

interface memory {
  resource accumulator {
    constructor(start: f64);
    add: func(value: f64);
    total: func() -> f64;
    merge: static func(a: borrow<accumulator>, b: borrow<accumulator>) -> accumulator;
  }
}

world calculator {
  export memory;
}
```

**Application code (component configured as `'acme:calc/memory': './calculator.wasm'`):**

```ts
import { Accumulator } from 'acme:calc/memory';

function handle(url: URL): Response {
  const acc = new Accumulator(0);
  for (const v of url.searchParams.getAll('v')) acc.add(Number(v));
  const merged = Accumulator.merge(acc, new Accumulator(10));
  return new Response(`${acc.total()} ${merged.total()}`);
}

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(handle(new URL(event.request.url)));
});
```

## What a Component May Import

After linking, a component may import only:

- `wasi:*@0.2.x` interfaces
- `gcore:*` interfaces

Any other import fails the build with `Components import interfaces FastEdge does not provide: <names>`.

A component can make outgoing HTTP requests through `wasi:http`. These requests go through FastEdge like the application's own `fetch()`, and the same rules apply (e.g., requests to private hosts are refused).

Outgoing HTTP, clocks, random, and stdio are the WASI interfaces used by the SDK's tested components. Do not assume that every allowed WASI interface works at runtime.

---

## Limits

Every request runs a fresh instance, so the work a component does is paid on every request. A request has a time and memory budget; on the free plan, 100 ms and 52 MB.

Check sizes before expensive work. In the image example, `dimensions()` reads only the image header and rejects images over a pixel limit before calling `resize()`.

**Measured performance on edge (image thumbnail component):**

| Image                     | Decode      | Whole component call | Memory |
| ------------------------- | ----------- | -------------------- | ------ |
| 612×640 JPEG (`kev.jpeg`) | ~10 ms      | ~20–30 ms            | 3 MB   |
| 1200×900 JPEG             | ~45–60 ms   | over 60 ms           | 9 MB   |
| 4000×3000 JPEG (12 MP)    | ~530–690 ms | over 700 ms          | 71 MB  |

Additional notes:

- Progressive JPEGs decode about 3× slower than baseline ones; save images as baseline.
- The component copies the image into its own memory for each call, so the bytes are held twice while it runs. That is small next to the decoded pixels (3 bytes per pixel for a JPEG).
- Raise pixel or size limits only on a plan with a larger budget.

## Build Errors

| Error message                                                                                                                    | Cause                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `--component expects <interface>=<path>, got "<value>"`                                                                          | A `--component` value has no `=`, or nothing before it.                                               |
| `Invalid component interface name: <names> (expected "namespace:package/interface")`                                             | The name is not `namespace:package/interface`, optionally followed by `@version`.                     |
| `Component "<path>" is not a readable file`                                                                                      | The path does not exist or cannot be read.                                                            |
| `"<path>" is not a Wasm component`                                                                                               | The file is not a Wasm component.                                                                     |
| `no component exports <interface>`                                                                                               | No given component file exports the interface.                                                        |
| `<interface> is exported by more than one component: <paths>. Components that export the same interface cannot be used together` | More than one component file exports the interface, even if `components` maps it to only one of them. |
| `Components import interfaces FastEdge does not provide: <names>`                                                                | After linking, an interface other than `wasi:*@0.2.x` or `gcore:*` remains imported.                 |

---

## Known Limitations

- A component whose exported interface uses types from another interface must also export that interface. Otherwise the build fails with the "does not provide" error for it.
- Components are linked in after the application is pre-initialized, so a component's own state is not pre-initialized. The first call in each request pays the component's start-up work.
- Two component files that export the same interface the application imports cannot be used in one build, even when `components` maps that interface to only one of them. The build fails with the "exported by more than one component" error.
